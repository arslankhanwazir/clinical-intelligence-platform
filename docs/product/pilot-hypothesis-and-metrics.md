# Pilot hypothesis and measurement definitions - M1 draft

## Pilot hypothesis - to test, not a proven benefit

At one selected Pakistan private primary-care clinic, a clinician-facing workflow that assembles the minimum authorized context for adult hypertension follow-up, makes data gaps and conflicts visible, presents approved evidence, and prepares a reviewable draft may reduce avoidable manual reconciliation and make documentation more traceable without removing clinician control.

This is a hypothesis only. No clinic baseline, user interview, time-savings result, clinical performance result or willingness-to-pay evidence has been collected in this M1 package.

## Baseline-first measurement plan

Measure the clinic's existing process before testing the assisted workflow. Agree collection method, sampling period, inclusion criteria, observer and privacy safeguards with the clinic and clinician. Do not capture real patient identifiers in this development repository.

| Metric | Definition | Baseline / target |
|---|---|---|
| Workflow duration | Median active time from the agreed start event to the agreed completion event; idle/wait time handled consistently. | Baseline TBD at clinic; target set after baseline and clinician review. |
| Context completeness | Applicable required context items available with usable provenance divided by all applicable required items. Required items must first be clinician-approved. | Baseline TBD; target TBD. |
| Missing/conflict flag agreement | Proportion of system flags adjudicated as relevant by the clinical reviewer, with missed material issues tracked separately. | No threshold set in M1. |
| Evidence traceability | Evidence-dependent draft statements with a valid, exact approved source reference divided by all evidence-dependent draft statements. | Define test protocol in M7/M10; target set by reviewer. |
| Draft correction profile | Counts and reasons for clinician edits, rejections and accepted drafts. Acceptance is not proof of safety. | Baseline not applicable to existing workflow; measure during supervised synthetic/usability evaluation first. |
| Workflow completion reliability | Successfully completed assisted workflow attempts divided by valid attempts; report failures by reason. | Target set after prototype baseline. |
| Usability | Clinician-reported usability using a preselected, documented method and participant context. | Method and threshold to be approved before evaluation. |

## Measurement safeguards

- Do not invent time-savings, quality improvements, clinical accuracy or economic return.
- Do not interpret clinician acceptance as proof of safety.
- Report denominators, exclusions, missing data and confidence/uncertainty with any later result.
- Numerical clinical safety and release thresholds are set by qualified clinical/safety reviewers in M10, not by the developer in M1.

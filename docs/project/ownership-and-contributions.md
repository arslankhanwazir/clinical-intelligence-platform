# Ownership, Clean-Room Development and Contributions

## Before external collaboration or public release
- Confirm who owns the repository, product name, code, domain, designs and other project assets.
- Review applicable employment, contractor, invention-assignment, confidentiality and non-compete obligations with qualified advice where necessary. This file is not a legal opinion.
- Maintain a dated record of original requirements, architecture decisions, design work and contributions.
- Use only code, models, datasets, fonts, images and documents with a reviewed licence and permitted use.
- Record each contributor's role and required IP/confidentiality agreement before accepting substantive contributions.

## Clean-room requirements
Develop from independently written requirements and public, cited sources. Do not copy or import confidential code, prompts, clinical protocols, datasets, customer information, internal documents, secrets, trade secrets or protected UI from third parties or former employers. Do not access systems or repositories without authorization.

## Contribution controls
- All changes through reviewed Git commits; no direct unreviewed changes to the protected main branch once remote collaboration begins.
- Every dependency and model must have a recorded licence, source and version.
- Synthetic test data must be clearly labelled and must not be derived from identifiable patient records.
- Keep a changelog for material clinical, security, rule and model changes.
